# 二、第一项改造：增加定价引擎，但不要破坏 Path-A

这是我认为你现有研究台最明显的升级机会之一。

目前 Path-A 的核心是20日与60日收益同向时顺势交易。它回答的是：

**市场有没有形成可识别的趋势？**

但它没有独立回答：

- 当前价格相对于基本面是否偏贵或偏便宜？
- 价格已经反映了多少利多或利空？
- 当前趋势有没有基本面支撑？
- 市场预期和基本面估值之间的差异是否足以覆盖交易成本？

因此，我建议增加一个独立的 `fair_value` 研究模块。

## 1. 模块如何设计

建议的目录：

```
pricing/
├── fair_value.py          # 公允价值与估值区间
├── valuation_deviation.py # 定价偏离度
├── basis_model.py         # 基差与期限结构
├── carry_model.py         # 持有成本与跨期关系
├── scenario_model.py      # 基本面情景估值
└── valuation_report.py    # 估值结果与解释

```

这只是建议的目标结构，不代表这些文件已经存在。

### 估值引擎需要输出什么？

每个品种统一输出：

| 字段 | 作用 |
| --- | --- |
| 当前价格 | 确定估值时点 |
| 公允价值中枢 | 基准估值 |
| 公允价值下限与上限 | 表示估值不确定性 |
| 定价偏离度 | 量化当前价格与估值之间的距离 |
| 估值变化方向 | 判断基本面是在改善还是恶化 |
| 估值置信等级 | 标记数据充分程度与模型可靠性 |
| 主要驱动变量 | 解释估值为什么变化 |
| 数据缺口 | 防止缺失数据被误认为真实信号 |

这里有一个关键设计原则：

**没有可靠估值的数据，不应该强行输出一个精确的公允价值。**

例如，商品期货可以通过基差、期限结构、库存、成本等建立估值模型；但对于缺少可靠供需数据的品种，系统应该明确标记估值能力不足，而不是用技术指标拼出一个貌似精确的数字。

## 2. 如何与现有策略连接？

初期不要让估值模块直接改变 Path-A 的入场条件。

应当先做三组对照：

- A组：现有 Path-A。
- B组：Path-A 加入估值偏离信息，但不改变交易。
- C组：Path-A 在估值偏离达到预设条件时调整交易决策。

先观察 B 组是否提供增量信息，再研究 C 组是否提高净收益或改善风险。

为什么要这样做？

因为估值可能有解释能力，却没有短周期预测能力。

比如某商品相对估值偏低，但可能在低估状态下继续下跌数月。估值适合帮助识别风险收益结构，不一定适合直接充当日内或短线入场信号。

**验收标准：** 估值模型必须证明它在样本外提供了独立价值，才能参与交易决策。

# 三、第二项改造：把现有信号整合为真正的方向识别系统

你现在已经有20/60趋势、席位、基差、波动率、HMM、事件因子，以及策略投票和综合评分。

因此，我不建议再新建一套重复的趋势评分模型。

我建议做的是：**统一信号接口，解决重复计分、信号冲突和预测目标不一致的问题。**

## 1. 为所有信号建立统一接口

建议每个信号都输出同样的字段：

```
{
  "instrument":
"CF2701"
,
  "signal_name":
"trend_20_60"
,
  "asof":
"示例时间"
,
  "direction":
1
,
  "strength":
0.65
,
  "confidence":
0.60
,
  "holding_horizon":
"中短期"
,
  "data_quality":
"valid"
,
  "evidence_level":
"research"
,
  "invalidation_condition":
"趋势方向反转"

}

```

以上是接口示例，不是实际行情或模型计算结果。

统一接口后，趋势、席位、基差、事件和波动率就可以在同一决策层中比较。

其中：

- `direction`：方向；
- `strength`：信号强度；
- `confidence`：经过历史验证或校准后的置信程度；
- `holding_horizon`：适用的持有周期；
- `data_quality`：数据是否足够可靠；
- `evidence_level`：该信号处于研究、回测还是模拟验证阶段。

需要特别注意，不能把主观打分直接当作统计置信度。置信度必须有明确的定义和校准方法。

## 2. 解决重复计分问题

例如，你现在的研究台同时观察：

- 20日动量；
- 60日动量；
- 均线趋势；
- 趋势突破；
- 趋势类模型投票。

这些指标可能都在反映同一个潜在因素：价格趋势。

如果把它们当作五个完全独立的证据相加，趋势就可能在综合评分中被重复放大。

我建议把信号先归为五个独立证据组：

| 证据组 | 现有模块 | 主要职责 |
| --- | --- | --- |
| 趋势 | Path-A、动量、突破 | 判断方向与持续性 |
| 定价 | 基差、期限结构、公允价值 | 判断相对价格是否合理 |
| 资金 | 席位、持仓量、成交量 | 判断参与结构 |
| 事件与基本面 | 事件因子、供需变化 | 判断驱动因素 |
| 风险状态 | ATR、波动率、HMM | 判断风险环境与信号可靠性 |

每个证据组内部先进行归一化和去冗余，再进入综合判断。

HMM 应当继续作为市场状态研究工具，与简单的趋势和波动率基准对照。你现有研究记录已经表明，HMM 与趋势模型联合门控的效果并不一定优于单独使用趋势模型，因此不应该让 HMM 自动拥有一票否决权。

## 3. 综合评分还应增加一个关键输出：信号冲突度

例如：

| 趋势 | 定价 | 资金 | 系统结论 |
| --- | --- | --- | --- |
| 偏多 | 低估 | 多头增强 | 多头证据一致 |
| 偏多 | 高估 | 多头减弱 | 趋势仍在，但追多风险增加 |
| 偏空 | 低估 | 空头增强 | 可能处于下跌趋势中的估值修复区 |
| 偏空 | 高估 | 空头增强 | 空头证据一致，但仍需考虑反弹风险 |
| 偏多 | 偏空 | 中性 | 信号冲突，等待确认 |

这里不应该仅仅计算一个加权平均值。

系统需要分别输出：

1. 综合方向；
2. 证据一致程度；
3. 各证据组的贡献；
4. 主要冲突来源；
5. 信号适用的持有周期；
6. 决策失效条件。

这样，你在研究台上看到的就不再只是一个“多头得分70分”，而是知道为什么是70分，以及哪些证据正在反对这个判断。

# 四、第三项改造：从方向预测升级到预期收益预测

这是整个系统最值得投入研究资源的部分。

现有方向评分主要解决“看多还是看空”，但真正决定交易价值的，是未来一段时间的收益分布。

我建议增加一个独立的 `expected_return` 模块。

建议结构：

```
research/
├── signal_fusion.py
├── expected_return.py
├── return_calibration.py
├── signal_conflict.py
└── trade_eligibility.py

```

## 1. 让系统预测三个结果

每个品种、每个预测周期，输出：

- 预期收益；
- 预期不利变动；
- 预期收益的不确定性。

例如：

| 指标 | 含义 |
| --- | --- |
| 预期收益 | 按既定持有周期估计的收益 |
| 预期最大不利变动 | 交易过程中可能遭遇的逆向波动 |
| 预期最大有利变动 | 交易过程中可能出现的有利波动 |
| 收益预测区间 | 对预测误差的量化 |
| 交易成本 | 预计完整建仓与退出成本 |
| 净收益预期 | 扣除成本后的收益估计 |
| 净收益风险比 | 预期净收益与风险预算的比较 |

这里需要避免一个常见问题：把未来最大有利变动和最大不利变动的实际数值当成实时可知信息。它们只能由历史样本预测，不能使用未来真实行情计算交易时点的决策输入。

## 2. 增加交易资格门槛

在现有信号之外，再增加一层判断：

$$
\text{可交易}
=
\text{数据合格}
\land
\text{风险合格}
\land
\text{净收益具有优势}
$$

例如，即使方向得分很高，只要预期收益不足以覆盖手续费、滑点和模型误差，就不应该强行交易。

反过来，估值偏离较大，但方向不确定，也可以进入观察状态，而不是立刻建仓。

最终可以形成四种决策：

- **允许交易**：方向、收益和风险均满足条件。
- **降低仓位交易**：存在优势，但信号冲突或不确定性较高。
- **观察等待**：存在研究机会，但尚未达到交易门槛。
- **禁止新增风险**：数据异常、组合超限或预期收益不足。

需要强调，这里的“允许交易”只是研究系统的决策输出，不代表自动下单。你现有 Path-A 仍然保持纸面验证、不接实盘的边界。

# 五、第四项改造：把 ATR 仓位管理升级为组合风险预算

你目前的 Path-A 已经使用 ATR 计算仓位，并且限制最多持有3个品种、总名义敞口不超过权益的50%。

这些限制可以保留，但还需要回答一个问题：

**名义敞口相同的两个组合，承担的实际风险可能完全不同。**

例如，持有三个低波动品种，与同时持有三个高波动品种，即使名义敞口一样，潜在损失也可能相差很大。

## 1. 建议增加独立的组合风险引擎

```
risk/
├── position_sizing.py       # 单品种仓位
├── portfolio_risk.py        # 组合风险
├── correlation_risk.py      # 品种相关性与风险聚集
├── drawdown_control.py      # 回撤控制
├── stress_test.py           # 极端情景
└── risk_state_machine.py    # 风险状态机

```

这些是建议新增或整理的模块，不代表仓库当前已有相同文件。

### 单品种仓位

保留现有 ATR 仓位框架：

$$
N_i=
\left\lfloor
\frac{R_i}
{ATR_i\times M_i\times K_i+C_i}
\right\rfloor
$$

其中：

- $R_i$ ：分配给品种的风险预算；
- $ATR_i$ ：价格波动尺度；
- $M_i$ ：合约乘数；
- $K_i$ ：止损距离系数；
- $C_i$ ：每手预计交易成本。

这只是初始仓位计算。还要考虑涨跌停、跳空、保证金、流动性以及组合约束。

### 组合风险

建议在现有名义敞口限制之外，增加：

1. 单品种风险上限；
2. 产业链风险上限；
3. 方向性风险上限；
4. 组合波动率预算；
5. 最大回撤降风险机制；
6. 压力情景损失上限。

特别是原油、甲醇等相关品种，不应只因为它们是不同合约就被当成完全独立的风险来源。

## 2. 不要急于引入复杂的动态仓位模型

我建议先比较三个版本：

| 版本 | 仓位规则 | 研究目的 |
| --- | --- | --- |
| A | 当前 ATR 仓位 | 冻结基准 |
| B | ATR＋组合风险预算 | 检验组合风控价值 |
| C | ATR＋组合风险预算＋信号质量调整 | 检验动态仓位的增量价值 |

三个版本必须使用相同的交易信号、数据、手续费和滑点假设。

评价时不能只看收益率，还要同时看最大回撤、尾部损失、换手率、保证金占用和不同品种的风险贡献。

如果 C 组的收益更高，但最大回撤和尾部风险显著恶化，就不能简单认定动态仓位模型成功。

# 六、第五项改造：让对冲优化器回答“怎么对冲最划算”

你目前已经有保护性期权的纸面机会、期权链对照、CF 棉花套保压力观察，以及期权相关研究模块。

所以这里不需要再建一个孤立的期权指标页面。

应该将它们统一到一个**对冲方案比较引擎**中。

建议目标结构：

```
hedging/
├── exposure_model.py       # 当前风险敞口
├── hedge_candidates.py     # 候选对冲工具
├── hedge_ratio.py          # 对冲比例
├── hedge_cost.py           # 对冲成本
├── hedge_evaluation.py     # 对冲前后风险比较
└── hedge_paper_ledger.py   # 纸面对冲记录

```

## 1. 每次风险预警，至少比较四种方案

| 方案 | 优势 | 主要代价 |
| --- | --- | --- |
| 不对冲 | 不产生额外对冲成本 | 保留全部原有风险 |
| 直接减仓 | 通常较简单，避免新增衍生品头寸 | 可能放弃后续收益 |
| 相关期货对冲 | 可以直接调整方向性敞口 | 存在基差和相关性失效风险 |
| 期权保护 | 可以为特定方向提供保护，部分方案损失相对明确 | 权利金、价差和波动率成本 |

期权对冲还应区分保护性买权、保护性卖权及其他组合策略的具体风险特征，不能将所有期权方案视为同一种保险。

## 2. 对冲优化的目标函数

建议将优化目标设为：

$$
\min_{h}
\left[
\lambda_1 \cdot ES_{\alpha}(h)
+
\lambda_2 \cdot C_{\text{hedge}}(h)
+
\lambda_3 \cdot C_{\text{residual}}(h)
\right]
$$

其中：

- $h$ ：对冲方案及其规模；
- $ES_{\alpha}$ ：指定置信水平下的预期尾部损失；
- $C_{\text{hedge}}$ ：交易、权利金、滑点和资金成本；
- $C_{\text{residual}}$ ：对冲后的残余风险成本；
- $\lambda_1,\lambda_2,\lambda_3$ ：风险偏好参数。

这些系数需要结合账户约束和压力测试确定。

另外，ES 和对冲成本不能简单地重复计算同一项损失。实施时要明确每个成本项的计量口径，并通过情景分析检验目标函数是否合理。

## 3. 以郑棉为例，系统应该怎样工作？

假设研究台识别到：

- CF2701 多头趋势仍然成立；
- 近期波动率快速上升；
- 基本面估值没有明显恶化；
- 某个事件可能导致短期大幅波动。

系统不应该直接得出“卖出棉花”或“买入保护性 Put”的结论。

它应当分别计算：

1. 维持原有多头的预期损失；
2. 减仓后的收益与风险变化；
3. 使用保护性 Put 后的权利金成本和压力损失；
4. 不同执行价格、到期日和持有期限下的对冲效果；
5. 对冲后的组合保证金及剩余风险。

最终比较的是**成本调整后的风险改善**，而不是哪种方案看起来更安全。

尤其要区分合成期权价格和真实可成交的期权报价。合成 ATR 权利金可以作为研究近似，但不能替代真实期权链、买卖价差和成交深度。

初期，这套引擎只需输出研究建议和纸面记录，不必自动执行对冲。

## 十、我认为最应该坚持的三条原则

### 原则一：Path-A 暂时不动，先建立可靠基准

不要在一次提交里同时修改趋势信号、仓位、止损、估值和对冲。

否则，即使结果改善，也无法判断是哪项改动真正有效。

保留当前 Path-A，逐个模块进行对照实验，结果才有解释力。

### 原则二：研究台上的评分不能直接变成交易指令

现有的综合评分、HMM、席位、基差和事件因子，都应当作为证据输入。

最终决策还必须考虑预测周期、预期收益、交易成本和风险预算。

一个高分信号，如果净收益预期为负，就不应该交易。

### 原则三：所有优化都必须允许失败

新增估值模型可能无效，HMM 可能不如简单趋势过滤，动态仓位可能增加换手，期权对冲也可能贵得不值得买。

这些不是研发失败，而是研究结论。

真正的失败，是模型没有通过验证，却因为看起来先进而被投入实际交易。

## 十一、下一步我建议直接做什么？

**先不要修改交易策略代码。先完成一次面向现有仓库的定向审计。**

审计只围绕四个问题：

1. **定价**：目前哪些模块真正计算了估值，哪些只是技术信号或基差观察？
2. **方向**：现有综合评分是否存在重复计分，哪些信号具有独立的样本外价值？
3. **风险**：现有 ATR 仓位、组合限制、回撤控制和压力测试是否形成完整闭环？
4. **对冲成本**：期权、相关期货和直接减仓是否能够在统一成本口径下进行比较？

随后形成一张逐文件的改造清单，明确哪些文件保留、哪些文件需要调整、哪些模块需要新增，以及每项修改的测试方法。

这样既能利用你现有的研究成果，也能避免把研究台改成一个越来越复杂、却无法证明有效的系统。

**我的建议是：下一步先做 `cta-path-a` 的四引擎专项审计，输出逐文件实施清单和验收测试方案；审计完成后，再逐项修改代码。**
